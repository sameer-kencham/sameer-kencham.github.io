The engineering challenge

Not just choosing moves. Learning from evidence.

The goal is a repeatable improvement loop: create chess training positions, learn a policy and position value, improve move selection with search, and compare against frozen baselines. The project combines model engineering, data quality, GPU optimization, and controlled evaluation.

System evolution

From LLM adaptation to a chess-native model.

Early experiments

Qwen3 and QLoRA

Prototyped a chess move-selection agent using Qwen3-8B and parameter-efficient fine-tuning. One recorded run trained on 20,433 examples using Unsloth QLoRA, establishing a baseline for supervised move selection and legal-output evaluation.

Custom V6 architecture

A specialized transformer

Moved toward a roughly 45.3M-parameter chess model with 64-square board tokens, eight-position history, geometry-aware attention, a 4,168-action policy representation, and a win/draw/loss value head.

Search and inference

PUCT + GPU evaluation

Added PUCT-guided search and batched GPU inference for comparing raw model preferences with searched moves. The work includes search-distillation experiments and matched configurations for more meaningful comparisons.

Data and experiment discipline

Reproducible comparisons

Used Stockfish/Syzygy guidance, self-play, versioned model candidates, game-disjoint data partitions, and paired-match scripts. Tracking individual changes matters more than making unsupported claims about absolute playing strength.
